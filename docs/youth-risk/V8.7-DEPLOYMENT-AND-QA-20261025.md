# OY-RALS V8.7 운영 홈페이지 반영·개선 기록

**대상**: `docs/youth-risk/` / 2026-10-25

## V8.7 변경 범위
- **SafetyState V8.7**: 공식 CORE를 점수·긴급판정의 단일 원천으로 유지. 1·2·7·25번 미상과 안전 추가확인 보류, 서술상의 현재 안전 신호를 별도 `reviewRequired` 값으로 일치시킴. 미상을 긴급 확정으로 처리하지 않음.
- **GoalComposer V8.7**: 25개 문항별 확인 행동과 근거 ID는 `ICMS.goals`에 모두 보존하고 실무자가 우선 검토할 목표는 최대 5개 묶음으로 출력. 자해·보호·성착취는 일반 생활지원과 별도 보호 맥락을 유지. 나머지 과제는 접기 영역으로 표시.
- **CaseState / 문서 정합성**: 종합사정·서비스계획·사례회의·초기상담·10영역 욕구사정이 같은 원점수·문항별 목표 및 근거를 공유. 초기상담·욕구사정은 묶음 목표 ID가 아닌 `g.item` 원래 문항으로 영역 매핑.
- **PrivacyGuard V8.7**: 외부 AI 요청문·개인 PC 로컬 AI 전송 서술을 최소한의 패턴 기반 식별정보 가림 후 미리보기 제공. 미리보기와 체크 확인 필요. 서술과 직접 기록을 ZIP에 포함하려면 다시 확인 창이 표시됨.
- **페이지·캐시**: 평가 / 사례검토 / 기록 / ZIP / 시스템 작동방법에 V8.7 로딩 순서 및 캐시 키 적용.

## 재현된 이전 오류와 수정
1. 공식 CORE가 미상으로 판단을 보류해도 V8.6 `safetyReviewRequired`가 false이던 오류 → 미상인 안전문항이 있으면 true.
2. 25문항 각각의 계획을 무조건 출력하여 과제 과잉·반복 → 3~5개 주요 묶음이 우선(근거가 적으면 3개 미만도 가능), 개별 목표 전체 보존.
3. 25문항 목표와 욕구사정표의 구간 매핑에서 목표 ID를 문자열 파싱해 빈칸이 생김 → 원본 item 번호로 매핑.
4. 서술형 정보를 외부 AI 요청문에 담을 때 직접식별정보 자동 가림 부재 → 인명 표시, 전화번호, 학교명, 이메일, 상세주소 유형에 대한 제한적인 가림과 수동검토 요구.

## 이번 기술 검수
- **5,000건 합성 입력**: 실행 오류 0, 공식 CORE 점수·긴급판정 변경 0, 안전 미상 누락 0, 원본 문항별 목표 누락 0, 주요 목표 5개 초과 0, 문서 원본 goal ID 불일치 0, 중복 원본 goal ID 0.
- **14개 화면·로더 연결검사**: 화면별 SafetyState/GoalComposer 선행 로딩, ZIP 로딩 순서, 개인정보 스크립트 준비 및 링크 캐시 정합성 검사 통과.
- **직접식별정보 예시**: 가상 이름·전화번호·학교명 가림 작동 확인.
- 재실행 스크립트: `tests/v87-integration-regression.cjs`
