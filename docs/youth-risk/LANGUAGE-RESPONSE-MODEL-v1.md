# OY-RALS 한국어 사례분석·근거기반 응답 모델 v1.0

- 기준: 2026-10-23
- 서비스: https://daily-jh.github.io/osansegyo-welfare-resources/youth-risk/
- 적용 화면: **3단계 사례검토 보고서·서비스계획안** 내 '평가자료에 질문하고 근거 있는 응답 받기'
- 저작·출처표시: 기존 청소년 시스템의 제작자 및 이용조건을 준용 (© 2026 김지훈)
- 성격: **비표준화 TEST · 규칙 기반 한국어 사정·응답 지원 엔진**, 임상·법적 판정기, 위험 예측모형, 독자 학습 LLM이 아님
- 구현: `language-response-model.js`, `language-response-ui.js`, `language-response.css`; `case-examples.html` 연계. `tests/youth-language-response.cjs` 품질검증.

## 1. 개발 목적과 기능 경계
상담·관찰 기록이 25문항 척도나 평가표로 완전히 표현되지 않는 문제를 줄이고 **현재 보고된 사실 → 추가확인 가설 → 실천 행동 → 담당/이행/재사정**의 논리를 명료화한다.

본 버전은 정규화된 언어 표현 10개 주제, 관련 문항 근거, 기존 24개 교차 검토 규칙, 복지자원 기관 매칭을 연결해 실무자의 질문에 **재현 가능한 한국어 문장**으로 답한다. 임의 가중치로 위험 점수를 다시 계산하거나 자살위험 확률·기대 성과를 제시하지 않는다.

| 데이터 계층 | 출처 | 반영 정보 | 안전/제한 |
| --- | --- | --- | --- |

| F. 문헌·법령 | 아래 공식 자료 | 안전우선, 학교-지역 협업 등 설계 원칙 | 문헌에서 미검증 가중치를 추정하지 않음 |

## 3. 한국어 질의응답 처리 흐름

1. **입력 검증**: 25개 응답, role, 자료형을 검사하고 외부 네트워크를 요청하지 않는다.
2. **주제 추출**: 서술을 문장단위로 분리하고 보호·또래·정서·학교·행동건강·가족돌봄·기본생활·교육접근·관계지지·디지털 10개 범주를 탐색한다.
3. **부정·상충 검사**: 주제 단어 뒤의 '없음/아니다/않다/부인' 등 간단한 부정표현을 검사한다. 이는 완전한 한국어 문장 의미분석이 아니므로 실무자의 재검토가 필요하다.
4. **채점과 보호 분리**: 공식 평가와 안전확인은 기존 `YouthMap.context` 기준을 그대로 사용한다. 서술의 주제는 점수 변경 없이 보조 가설과 확인 질문에만 쓴다.
5. **근거 결합**: 각 범주에 매칭된 공식 문항번호·점수와 서술의 문장번호를 병기하고 `YouthEvidenceMatrix.evaluate`의 실제 발화 조건을 충족한 교차 가설을 가져온다.
6. **질문 분류**: 안전 / 지역기관 / 서비스계획 / 면담 질문 / 근거 검토 / 종합 사정 중 요청을 분류한다. 사용자가 기입한 자유질문 전체를 이해하는 생성형 모델은 아니다.
7. **응답 합성**: 먼저 안전을 표시하고, 사실과 해석가설을 구분하며, 실무자별 확인 질문과 권역 자원 후보를 정리한다.
8. **품질고지**: 지원기관의 실제 대상·접수 조건은 미검증이라고 표시하고, 현장 담당자 검토 후에만 대외 기록/의뢰에 사용한다.

## 4. 안전 불변조건 (invariants)

- 안전 핵심문항 **1·2·7·25**의 양성 신호 및 명시적 긴급 체크는 총점과 무관하게 현재 안전을 우선한다.
- 4·5·12·13번 조건부 추가확인의 '미확인'은 위험발생의 확증도, 안전확인의 완료도 아니다.
- 숫자 0은 관찰·보고된 어려움이 없다는 응답이고, `unknown`은 아직 확인하지 못했다는 응답이다. **0과 unknown을 합산하거나 서로 대체하지 않는다.**
- 사례판정/권역매칭 결과는 참고 제안이며, 학생맞춤통합지원 대상·법적 신고 여부·임상진단·지원 자격·실제 기관 수용 여부를 확정하지 않는다.
- 상담기록에 등장한 학대·자해·성착취는 문맥/현재성/부정 여부를 직접 확인한다. 서술문 단어의 출현만으로 긴급사실을 확정하거나 원점수를 수정하지 않는다.
- 1권역 오산세교종합사회복지관: 신장1·신장2·세마. 2권역 오산종합사회복지관: 남촌·중앙. 3권역 오산남부종합사회복지관: 대원1·대원2·초평. 실제 이용 자격 확인.
- 기기 내 메모리 저장 외 서버 송신 없음. 단, 복사·인쇄·기록물 처리나 연결된 타 AI 사용 시 개인정보 위험이 별도로 발생할 수 있음.

## 8. 테스트 전략·평가 지표
자동검사: `node tests/youth-language-response.cjs`. 자동검사는 0~4/미상·행정동 3개 권역·부정표현·안전 우선·점수변경 금지·문항 교차가설·입력 불변성을 대상으로 하고, 2개 결정적 시드의 가상자료 4,000개를 추가한다. **기술적 회귀검사이지 인간 사례 분류 정확도·재현율 또는 서비스 효과성의 증명은 아님**.

실사용 검증(향후 기관 내부 승인 필요):
- **전문가 평가**: 교사·사회복지사·청소년 상담 전문가가 완전 비식별/합성 사례를 사용해 근거 적합성, 상담 안전성, 문장 비약, 기관 매칭 적합성을 검수.
- **실측 지표**: 사안별 안전 미탐 및 오탐 건수, 부정문 오류율, 문항–서술 상충 탐지의 정밀도/재현율, 금지된 진단 문구 발생, 권역 일치도, 대상기관 자격 확인률, 문장 근거 추적 가능률.
- **원칙**: 0건 오류를 확신하는 표현 금지; 실제 타당도·민감도·특이도 수치는 현장 사례자료와 전문 연구설계 없이 산출하지 않음.

## 9. 차기 단계: 자체 LLM 및 RAG 고도화
- 규칙 엔진을 **점수/안전 판정의 유일한 권위 데이터**로 유지하고, 선택형 생성형 모델은 출력 문장 작성에만 사용하도록 분리한다.
- 법령·논문·기관 DB를 검수된 출처와 날짜를 보유한 **문서 청크(JSONL)**로 색인하고, 질문별 검색·참조 IDs를 함께 전달한다.
- 보호되는 학생 자료를 공개 GitHub, 공개 이슈, 모델 학습 로그 등에 저장하지 않는다.
- 외부 API 연결은 서버 측 비밀키 보관·기록 보존정책·접근 권한·개인정보 처리근거·외부 전송 동의를 갖춘 다음에만 선택적으로 도입한다.
- 실제 사례기록을 사용한 파인튜닝은 원칙적으로 하지 않고, 비식별 합성 사례 및 저작권 허용된 공개 규정 자료만 사용한다.

## 10. 운영자가 알아야 할 핵심 한계
현재 v1은 서술 키워드 기반이므로 '피해가 없었다', '피해를 당했다고 들었다'처럼 사건의 현재성·전언성·인용·부정·행위주체를 완벽히 이해할 수 없다. 사이트가 답변을 생성해도 **사실로 확인된 것이 아니다.** 고도화된 한국어 이해나 생성형 AI가 꼭 필요한 경우, 검증된 추가 구성요소로 확장해야 한다.
