# OY-RALS 사례관리 단계 연속성 엔진 사용·검수 지침
2026.10.23 | 2026.10.case-continuity-v1 | 비표준화 실무검토용

## 적용 범위
25문항 위기평가·안전판정·기관추천 엔진과 별개로 운영하는 5단계 **문서·실행 연속성** 검사입니다.

1. 초기 사정: 응답·출처·강점·기존 서비스·학생 의사
2. 1차 사례판정회의: 논의안, 채택, 수정, 보류, 미기록의 구분
3. 서비스계획: 목표·기관 역할·기간·합의·계획 확정 여부
4. 서비스 제공·점검: 예정, 문의, 의뢰, 접수, 개시, 완료 및 증빙
5. 점검회의: 원안 유지, 일부 수정, 재수립 및 미결정

**유의:** 기존 복지관의 다른 위기도 척도로 산출한 점수를 청소년 25문항·100점 점수로 변환하는 기능이 아닙니다. 문항별 값이 없으면 청소년 척도 총점·등급은 '미확인' 상태로 둡니다.

## 사이트 사용
청소년 위기평가 → 결과·지원연계 → 선택기능 '기록·점검' → **사례회의·서비스계획 이행점검**.
평가 결과에서 확인된 영역별 가상 과제를 초안으로 표시하며, 학교/복지관 회의록과 기관 제공확인 문서를 실무자가 직접 검토하여 선택합니다. 청소년 척도로 포착되지 않는 **강점·진로·가족차원의 목표**는 별도 추가 목표로 입력할 수 있습니다.

- 평가 점수로 사례선정·기관제공 사실을 자동 확정하지 않습니다.
- '회의 채택 4/4'는 이행·효과를 뜻하지 않습니다.
- '원안 유지'는 기존 목표를 유지한다는 회의결정이며, 접수·제공·완료 상태와 별개입니다.
- '완료'라고 입력했어도 문서증빙이 없으면 완료근거 **미확인** 경고를 표시합니다.
- 이미 제공 중인 서비스가 있으면 신규 연계 중복 여부를 점검합니다.
- 1차와 후속 사례유형이 다르면 회의의 유형 변경 근거를 확인하도록 알립니다.
- 동일한 우선순위 번호가 반복되면 공동순위인지 서식 오류인지 확인하도록 합니다.
- 학대·자해·성착취 등 안전·신고는 계획일치율보다 우선합니다.

## 데이터 구조
- 구성 DB: `data/case-continuity-rules.json`
- 로직: `case-continuity-model.js` (정적 오프라인 분석, 브라우저만 사용)
- 실무자 입력·출력: `case-continuity-ui.js`, `workbench.html` → 기존 서비스계획 보고서 인쇄/출력에 포함
- 합성 기술시험: `scripts/test_youth_continuity.cjs`
- 저장소의 구성 DB는 외부 서비스 데이터베이스가 아닌 **버전형 정적 JSON 규칙표**입니다.
- 페이지의 동일 출처 정적 JSON만 읽으며 사용자가 입력한 학생·가족 정보는 서버에 전송하지 않습니다.
- 임의 브라우저 종료 후 입력을 자동 복구하거나 영구 저장하지 않습니다.
- PDF 원문 자동 파싱·비식별화 기능은 **없습니다**. 이 기능에 실명·주소·의료이력·상담내용을 입력하지 않습니다.

## 시험과 품질 한계
고정 시드 합성 상태 10,000건에서 예외와 주요 회의·계획·제공상태 불변조건 오류 0건 확인.
검사 대상: 실제 계획 완료 증빙 확인, 회의 미기록, 기존 서비스 중복, 사례유형 충돌, 우선순위 번호 충돌, 원안 유지/실행 분리.
이는 **코드 정합성 검사**이며 실제 사회복지사 간 판정일치도, 임상적 정확도, 서비스 효과, 학생의 삶의 변화, 복지관의 법정 권한을 검증한 것이 아닙니다.
