# V8.6 ZIP 내보내기 경로 검수 및 수정

**적용일:** 2026-10-25

## 발견 원인
1. `bundle-export.js`의 `modules()` 로더가 V8.6 원본 6개 모듈을 불러오지 않고 V8.3 시점 스크립트 캐시 키를 사용하여, 일반 화면과 ZIP 파일 간 모델 버전·해석 결과가 달라질 수 있었음.
2. `site-bridge-v86.js`에서 전체 개입목표의 `domains`를 빈 배열로 설정해, `case-analysis-v83.js` 영역별 지원표가 각 문항의 차별화된 행동을 찾지 못하고 공통 문장으로 대체함.

## 변경
- 원본 `case-evidence-base-v86.js` → `evidence-v86.js` → `item-action-router-v86.js` → `reconciliation-v86.js` → `unified-v86.js` → `site-bridge-v86.js` → `oy-rals-v86-site.js` → `case-formulation-v72.js` 순서 보장
- 브라우저·ZIP 로더·부모 메인페이지 `v=20261025-v86-bundle-verified`로 캐시 갱신
- 각 Q01~Q25를 기존 CORE 10영역 문항 분배 `[2,3,3,3,2,2,3,3,2,2]`에 맞게 연결. 점수와 안전 게이트 변경 없음
- `assessment.html`, `case-examples.html`, `workbench.html`의 Bridge 캐시 버전 갱신
- `tests/v86-zip-export-regression.cjs`에 **독립 합성** 시험값과 모델 로딩 순서·영역 행동 검사를 등록; 실제 학생의 서술·평가값은 저장소에 포함하지 않음

## 확인
- 업로드 파일의 원점수 계산은 일치하나 이전 ZIP에는 V8.2.1 문구, 서로 다른 낮은 점수 영역에 반복된 보호 대응, 초기상담·욕구사정 항목의 분류 누락이 있었음.
- 새 통합코드 재현 점검: 해당 합계의 **비식별 동일 점수형** 런타임 검사에서 V8.6 버전 사용과 영역별 과제 분리 확인.
- 25개 단일 고점 문항 시험: 영역 할당 누락·다른 영역으로 안전조치 복제·기존 CORE 점수/긴급판정 변경 0건.
- 브라우저 내보내기 ZIP을 이용한 실제 모바일 종단간 수동 검증은 별도 진행해야 함.
